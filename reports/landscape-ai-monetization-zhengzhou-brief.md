## 0. 写给管理层的一页纸（先看这里）

### 0.1 系统到底要干什么？（目的必须先讲清）

| 层次 | 表述 | 是否主目标 |
|------|------|------------|
| **商业目的** | 在设计本业上延伸**使用期可收费服务**（建档、监测、报告、轻诊断、续费） | ✅ 对公司而言的目的 |
| **专业目的** | 让景观资产**可管理、可证明、可追溯**（责任边界、验收、绩效） | ✅ 对客户最有感 |
| **效率目的** | 减少漏检、空跑、重复扯皮，提高巡检与响应效率 | ✅ 手段与附带结果 |
| **常见误解** | “用 AI 大规模替代园艺/保洁人工、靠裁员降本” | ❌ **不是**系统总目的 |

**一句话目的：**

> AI 用来把景观从「建完即结束」变成「可监测、可追溯、可维护、可收费」的资产服务；  
> **少做无效人工是结果之一，不是唯一目的。**

**目的优先级（对外对内统一口径）：**

```text
① 可证明（维保责任、验收、政府绩效）  ← 最能收钱
② 可管理（告警、派单、台账）
③ 可提效（少漏检、少空跑）
④ 可替代部分重复劳动（有限、渐进）
```

### 0.2 一轴两翼（现场与回程汇报结构）

```text
              【以设计本业为圆心】
                       │
     ┌─────────────────┴─────────────────┐
     ▼                                   ▼
【左翼：设计增项——立刻做】           【右翼：数字化年费——稳步试】
· 施工图增加《监测/巡检预留标准》     · 资产数字建档（企微轻量化）
· 投标附加《维保期数字证据方案》     · 雨季排水/长势异常 · 工单
· 挣一次性方案溢价与技术门槛         · 锚定大型公建/高端园区/城更
                                     · 先切开发商维保期与政府绩效的钱
```

### 0.3 三条作战红线（防“方案很性感、落地成先烈”）

1. **硬件红线**：首年不做高密度地下物联网；默认「手机巡检 + 视觉抽帧 + 规则引擎」，传感器仅关键点极少量验证。  
2. **付费红线**：不把「穷物业的预防性年费」当第一枪；优先开发商维保期、政府后评价/审计材料。  
3. **法律红线**：可做地表排水与覆土异常巡检；**不出具结构防渗漏合规结论**；成活率报告定位为过程证据，不替代质保责任认定。

### 0.4 战术两步

- **借鸡生蛋**：白标/OEM——对方提供平台、算法与供应链，我方套品牌 UI + 景观规范与费项。  
- **标杆闭环**：选 1 个维保期在建/刚交付项目或城更项目，出第一份付费《雨季排水/长势监测报告》，验证买单意愿。

## 1. 目的、非目的与原则

### 1.1 此行要达成什么

1. **技术面**：从图纸交付延伸到使用期「感知—派单—报告」；  
2. **产品面**：形成可报价、可复制、可续费的服务包；  
3. **收入面**：设计费之外增加监测、报告、轻改造建议、年费；  
4. **合作面**：摸清对方工程化能力（误报、断网、规则引擎），谈白标可行性。

### 1.2 明确不做 / 不主推

| 不做或不主推 | 原因 |
|--------------|------|
| 变成种植大户 / 农业公司 | 离客户与交付太远 |
| 立刻自研完整对标平台 | 周期长、重复造轮子 |
| 只把 AI 写进投标 PPT | 无法续费、无法验证 |
| **以「替代人工降本」为对外总叙事** | 难收款，易被当成免费管理配套 |
| **首年高密度室外传感器方案** | 维护成本常高于探头本身，先烈风险高 |
| **出具结构防水/渗漏合规类报告** | 责任过重，官司高发 |

### 1.3 核心原则

> **AI 不是目的，是把景观变成可监测、可诊断、可在硬约束下轻干预、并可收费的服务。**

硬质结构（景墙、主管线、主体铺装骨架）往往不能随意改动。AI 的价值在于：

- **看见偏离**（积水、死苗、灯失效、抄近路……）；  
- **判断轻重**（管理可解 / 轻改造 / 必须专项）；  
- **给出可逆方案**（不拆主结构）；  
- **留下证据链**（服务维保争议、验收与绩效）。

## 2. 付费方矩阵（v1.1 关键修正）

> 原思路易默认「物业买单」。现实中多数物业是成本中心，预防性数字化年费难卖。  
> **付费场景尽量前移。**

| 付费方 | 痛点 | 可卖什么 | 优先级 |
|--------|------|----------|--------|
| **开发商（维保期 1–2 年）** | 成活扯皮、积水维权、退保函 | 数字化维保监控、责任边界证据、季报 | ★★★★★ |
| **政府城更 / 海绵 / 专项债** | 绩效后评价、结项审计 | AI 辅助量化报告进审计交付物 | ★★★★★ |
| **园区业主 / 酒店甲方** | 品质与投诉、品牌形象 | 建档 + 巡检年费 | ★★★★ |
| **物业** | 编制紧、怕投诉 | 作为**执行与接单方**；买单能力弱时不作第一枪 | ★★☆ |

**物业角色校准：** 常用系统的人 ≠ 付钱的人。合同设计上可让开发商/业主付费，物业账号使用。

**防「维保期吃完就断」：** 台账与历史报告约定可迁移给大业主/运营商，预埋第二年续费口径。

## 3. 技术路线：低感知轻资产（v1.1 关键修正）

### 3.1 为什么不能一上来上满传感器

室外探头常见命运：泥沙包裹、受潮腐蚀、割草误伤、雷击、供电难、维护费超过设备费。  
「管网异常、水力平衡、渗透衰减」等能力若强依赖密布探头，**方案很美、现场先死**。

### 3.2 默认技术栈（Phase 0–1）

| 层级 | 做法 | 说明 |
|------|------|------|
| 主力 | **保安/保洁/园工 · 企微扫码巡检**（边缘众包） | 低成本、可培训、可留痕 |
| 主力 | **园区已有摄像头抽帧**（计算机视觉） | 优先公区积水/水景等非人脸场景 |
| 规则 | **低代码规则引擎**（业务可配） | 比“有模型”更关键 |
| 辅助 | **极少量** LoRa/4G 太阳能液位等 | 仅总调蓄、关键跌水井、易涝点 1–2 个 |
| 暂缓 | 高密度土壤/管网地下物联网 | 证明付费与闭环后再考虑 |

**成功指标：** 工单有人看、有人处理、客户愿付费——**不是测点密度。**

### 3.3 传感器分期

- **Phase 0–1**：无感/低感为主；  
- **Phase 2**：证据增强型极少量探头（服务争议现场与政府过程线需求）；  
- 传感器**不当利润中心**。

### 3.4 摄像头合规

住宅摄像头抽帧需注意隐私与业委会态度；默认以**巡检拍照上传**为主，固定摄像头为辅，避开人脸识别叙事。

## 4. 法律与责任边界（必须写进产品与合同）

| 可做 | 不可做 |
|------|--------|
| 地表积水、雨水口堵塞、覆土过湿等**表症巡检** | 出具「结构防渗漏合规 / 无渗漏」结论 |
| 长势异常、疑似死苗的**过程记录与派单** | 单方面「判定施工不合格」替代质保鉴定 |
| 照明薄弱、铺装破损等安全提示 | 承诺替代结构、防水、机电专项责任 |
| 报告定位：**AI 辅助 + 专业复核** | 宣称全自动免责替代人工专业判断 |

**屋顶/车库顶产品定义（收窄）：**  
「地表排水顺畅度与种植覆土状态巡检」——渗漏专业责任归土建/防水维保方；我方发现异常即**转介**，不背书。

**成活率：** 报告 = 养护动作与异常时间线证据，服务扯皮澄清，不替代合同质保条款。

## 5. 行业痛点：设计意图为何在生活中失效

| 驱动因素 | 典型后果 |
|----------|----------|
| 居民真实行为 | 抄近路、占扑救面、庭院变晾晒 |
| 气候与极端天气 | 暴雨积水、干热死苗 |
| 养护预算与能力 | 雨水口堵塞、灌溉失当 |
| 材料与隐蔽工程老化 | 反坡、灯失效、屋面渗漏风险 |
| 树木改变光环境 | 座椅不可用、夜间不安全 |
| 硬结构不可改 | 问题可见却不能推倒重来 |

**结论：** 后期生意卖的是 **后评估 + 约束下轻干预 + 证据链**，不是「再设计一遍」。

## 7. 植物以外：AI 更该盯的付费相关议题

阳光、雨水影响生长是基础；以下往往**更贴近付费动机**（投诉、索赔、验收、安全）：

| 议题 | AI/系统可做 | 不拆主结构的干预 | 优先买单线索 |
|------|-------------|------------------|--------------|
| 排水与雨季效能 | 积水对比、雨水口状态、工单 | 清淤、导流、值守 | 开发商维保、城更 |
| 真实使用偏离 | POE、抄近路/占用分析 | 引导软景、家具、管理 | 开发商示范区反馈 |
| 夜间照明 | 薄弱区、故障上报 | 补灯、调灯、节能 | 物业执行，业主付费 |
| 铺装与适老安全 | 破损、积水反光提示 | 局部更换、防滑 | 城更、老旧小区 |
| 水景机泵 | 运行与异常工单 | 策略调整或改旱 | 物业成本痛点 |
| 阀井可运维 | 二维码台账、定位 | 不改管线走向 | 降抢修成本 |
| 屋顶/立体层表症 | 积水、溢流、过湿巡检 | 转介防水专项 | 高客单但责任收窄 |
| 植物长势 | 对方强项，我方包装进维保包 | 养护策略 | 维保期成活争议 |

## 8. 可收费产品包（修订版）

### 包 A｜景观资产数字建档（入门）

企微扫码台账（植物/井/阀/灯）；竣工对照。  
**收费：** 按项目一次性。  
**买单：** 开发商移交专项 / 园区甲方。

### 包 B｜雨季排水效能巡检（强付费动机）

雨前雨后对比、积水热点、雨水口状态、工单与季报。  
**技术：** 巡检照片 + 可选摄像头抽帧；关键井极少量液位仅作增强。  
**收费：** 雨季按次或维保期打包。  
**买单：** **开发商维保**、城更绩效材料。

### 包 C｜设计 + 维保期智慧监护（续费预埋）

设计预留巡检点与编码；移交建档；维保期长势/积水异常告警与季报。  
**收费：** 设计增项或维保期专项；第二年转业主年费口径。  
**买单：** 开发商；物业接单执行。

### 包 D｜入住后 AI·POE + 轻改造菜单（咨询）

行为与投诉摘要；管理/软景/家具/局部铺装分级建议；**不碰主景墙与主管线**。  
**收费：** 报告费 + 可选轻改设计费。

### 包 E｜屋顶/立体层「地表状态」体检（收窄定义）

只做地表排水顺畅与覆土过湿等表症；**不写结构防渗漏结论**；异常转介土建防水方。  
**收费：** 按地块按次。

### 干预分级（与报价绑定）

| 级别 | 含义 | 举例 | 收费 |
|------|------|------|------|
| L0 管理 | 制度与养护即可 | 清雨水口、调开灯 | 含巡检 |
| L1 可逆轻干预 | 不动主结构 | 导流、补灯、软景引导 | 小额增补 |
| L2 局部工程 | 小范围 | 局部返坡、阀井抬升 | 单独报价 |
| L3 结构性课题 | 需专项 | 景墙开洞、主管改线、防水大修 | **只诊断+转介** |

## 9. 合作模式与郑州现场「杀手锏」三问

### 9.1 合作模式

| 模式 | 说明 |
|------|------|
| **白标 / OEM（首选）** | 底层用对方，对外贝尔高林品牌与景观规范 |
| 项目联合体 | 设计中标后联合报维保监测 |
| 渠道分润 | 我方出客户关系 |
| 标准共建 | 《可运维景观巡检与预留导则》 |

### 9.2 对方壁垒往往在「脏活」不在算法——必挖三问

1. **假阳性 / 误报如何压到工人愿意看、而不是关通知？**（树影、雨水反光、落叶）  
2. **弱网/断电如何缓存与补传？** 室外网关通信是 LoRaWAN、Cat.1 还是其他？  
3. **规则引擎是否低代码？** 业务人员能否配置：  
   `连续降雨>50mm 且 液位A>0.3m → 预警分区B并派单班组长`  
   若具备，景观场景可快速适配。

### 9.3 其他必问（商业与边界）

- 实施费 vs 年费比例、客单价、续约率、不续约原因；  
- 是否与设计院合作过分润；  
- 无传感器时最小可售版本是什么；  
- 私有化/内网、API、企微对接；  
- 有无屋顶绿化、车库顶表症巡检案例（非防水鉴定）；  
- 积水、铺装破损是否在路线图中。

## 10. 设计左翼：可立刻变成图纸与投标交付物

勿停在理念，要变成：

1. **监测/巡检预留图层**（井号、扫码点、电源、摄像头可视域示意）；  
2. **资产编码表**（移交 Excel + 二维码规则）；  
3. **投标一页纸：《维保期数字证据方案》**（打开发商退保函与索赔痛点）；  
4. 可选：海绵/排水效能「可监测」叙述（有点位与报告样例支撑，避免空泛预演）。

## 12. 90 天落地与成功定义

| 阶段 | 时间 | 动作 |
|------|------|------|
| 决策 | D+7 | 定白标意向、首选包 B 或 C、产品 Owner |
| 标准 | D+30 | 编码表、预留图层、合同免责条款模板 |
| 试点报价 | D+45 | 绑定 1 个维保期或城更项目，**独立费项** |
| 试运行 | D+90 | 出第一份客户用于实际决策的报告 |

**第一年成功定义（不亏优先于规模）：**

> 签回 **1 个付费试点**、毛利不为负、报告被甲方用于 **索赔澄清 / 验收 / 结项** 至少一次——不是 ARR 叙事。

## 14. 给管理层的结论句

对方最值得学的不是「种植 AI」四个字，而是：

> **工程化可用的管理闭环 + 可配置规则 + 可忍受的误报水平；**  
> 我们用来支撑**维保期证据与政府绩效类付费**，并以白标方式贴上景观专业与品牌。

植物与光雨水是入口；**排水表症、使用偏离、照明安全、阀井台账、立体层地表状态**是扩展面。  
**先付费试点，再谈自建平台；先工单闭环，再谈密布感知。**
