# 景观设计 × AI/IoT｜增值点集成策略（非新业务线）

**贝尔高林 · 郑州集团下属 AI（种植 / 绿地 / 医院数字孪生）企业拜访回程对齐材料**  
**拜访日期：2026年9月15–16日**  
**版本：v2.0｜修订说明：按老板现场结论改写——不新开 AI/IoT 业务线；将合作方成熟能力作为景观项目交付内的增值点集成（设计溢价、投标差异化、可选甲方自采模块 + 我方选型/接口）**

---

## 0. 给管理层的一页纸（先看这里）

### 0.1 本次考察的结论（对齐口径）

| 判断 | 说明 |
|------|------|
| **不做** | 不新开独立 AI / IoT / SaaS 业务线，不设新的 P&L，不自建对标平台，不主推农业物联网卖给农场主 |
| **要做** | 把合作方**已跑通的成熟能力**，嵌进景观**设计本业交付**，变成可报价的增值点 |
| **钱从哪来** | 仍落在设计费溢价、中标概率、项目总包/专项中的可选模块——不是另起炉灶收「平台年费帝国」 |
| **我方角色** | 场景定义、景观规范、选型与接口、图纸预留、投标叙事；底层算法/传感/工单平台可白标或甲方自采 |

**一句话：**

> AI/IoT 是景观项目的**增值配件与差异化武器**，不是贝尔高林的下一条赛道。  
> 合作方负责「能用」；我们负责「嵌得进设计与投标，且责任边界清楚」。

### 0.2 增值点三路径（替代原「一轴两翼年费叙事」）

```text
                 【圆心：景观设计本业交付】
                            │
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
 【路径① 设计溢价】    【路径② 投标差异化】   【路径③ 可选模块】
 施工图/说明书增加       方案与标书写入         甲方有预算时自采
 巡检点、编码、预留       「可运维/可证明」      传感器·平台·工单
 挣一次性技术增项         提高中标与议价         我方做选型+接口
                                              不做自营运维 P&L
```

### 0.3 三条红线（防跑偏）

1. **组织红线**：不设「AI 事业部 / 独立产品公司」叙事；考核仍归设计项目与商务中标。  
2. **硬件红线**：默认低感知（巡检拍照 + 既有摄像头抽帧 + 规则）；传感器仅关键点可选，不当利润中心。  
3. **法律红线**：可做表症巡检与过程证据；**不出具结构防渗漏合规结论**；成活率材料不替代质保鉴定。

### 0.4 现场带走的两条能力（怎么用、怎么不用）

| 对方能力 | 对我们有用的用法 | 明确不用 / 降级 |
|----------|------------------|-----------------|
| **医院数字孪生 + 工单闭环** | 学「资产身份化 + 告警—派单—留痕」的粘性；迁移到园区/酒店/高端公建景观运维叙事 | 不照搬医院 IT 大集成、不承诺替甲方建全院级孪生 |
| **农场 / 种植 IoT** | 学传感、规则引擎、误报治理的工程脏活；包装进**维保期成活/长势证据**或园区品质包 | **不卖农田物联网**；农业客群与交付离本业太远 |

**场景优先级（写进对外材料）：** 园区 / 酒店 / 高端公建 / 城更示范段 ≫ 住宅物业纯年费 ≫ 农田。

## 1. 战略定位：增值点集成，不是新业务线

### 1.1 为什么不是新业务线

| 若做成新业务线 | 风险 |
|----------------|------|
| 自研/自营平台与运维团队 | 研发与现场实施吞噬利润，与设计产能抢人 |
| 以 ARR / 年费为 KPI | 付费方常是物业成本中心，销售周期长、续约难 |
| 与合作方对标竞品 | 重复造轮子，且我们无传感供应链优势 |
| 农业 / 泛 IoT 扩张 | 客户、交付、回款逻辑与设计院主业脱节 |

### 1.2 增值点集成的定义（对内统一）

> **在既有景观项目合同结构内**，增加可选项或标配技术条款：  
> 预留标准、编码移交、监测/巡检方案、可选硬件与平台接口说明；  
> 由合作方提供成熟产品，贝尔高林提供**专业场景包装、图纸与接口、品牌与客户关系**。

**成功指标（第一年）：**

- 至少 **1 个在谈/在建项目** 的图纸或标书写入可运维预留条款；  
- 至少 **1 次** 投标材料使用「数字证据 / 可运维景观」差异化话术并进入短名单或加分讨论；  
- 可选模块若成交，毛利来自**设计增项 / 选型咨询 / 接口协调费**，而非自建机房与运维编制。

## 2. 我方 / 合作方分工（责任切清楚）

| 事项 | 贝尔高林 | 合作方（白标/OEM/甲方自采） |
|------|----------|----------------------------|
| 场景与规范 | ✅ 景观点位、编码、巡检逻辑、报告口径 | 提供可配置规则与行业模板参考 |
| 图纸与投标 | ✅ 预留图层、说明书、一页纸方案 | 提供产品彩页、案例参数（脱敏） |
| 平台 / App / 算法 | 品牌 UI 可贴牌时参与验收 | ✅ 产品主体与升级 |
| 传感与施工安装 | 选型建议、点位图 | ✅ 供货、安装、维保（或甲方指定） |
| 日常运维坐席 | ❌ 不建 7×24 运维中心 | 按合同由物业/业主/合作方 |
| 结构/防水鉴定 | ❌ 不做 | ❌ 亦不替代专项责任 |

**三种采购落位（商务可选）：**

1. **设计增项内含**：预留与方案费进设计合同；  
2. **联合体/分包**：中标后合作方作为专项分包；  
3. **甲方自采**：业主直采平台与硬件，我方出《选型与接口说明书》收咨询/配合费。

## 3. 考察启示 → 可落地的增值点菜单

### 3.1 从医院孪生学到的（迁到景观）

- **身份化台账**：植物、雨水口、阀井、灯具 = 可扫码资产；  
- **工单粘性**：异常必须有人接、有人关、有时间戳——比「模型准确率」更能留住客户叙事；  
- **绩效材料**：政府/城更/开发商维保更买「可证明」，不是买「很 AI」。

### 3.2 从农场 IoT 学到的（只取其工程，不取其客群）

- 规则引擎低代码、弱网补传、误报过滤——这些是**选型必考题**；  
- 密布土壤探头在室外景观场景**首年不主推**（维护成本常高于探头）；  
- 默认技术栈：**企微/手机巡检 + 视觉抽帧 + 少量关键点传感（可选）**。

### 3.3 可写入项目的增值点（产品化表述，仍属本业）

| 编号 | 增值点 | 嵌入方式 | 典型买单位置 |
|------|--------|----------|--------------|
| V1 | 《可运维景观巡检与预留》图层 + 编码表 | 施工图/移交 | 设计增项 |
| V2 | 《维保期数字证据方案》一页纸 | 投标附件 | 提高中标/溢价 |
| V3 | 雨季排水表症巡检包（照片对比 + 工单） | 维保期专项或甲方自采 | 开发商维保、城更 |
| V4 | 园区/酒店品质巡检年费（合作方运营） | 甲方自采或联合体 | 业主；我方接口费 |
| V5 | 屋顶/车库顶「地表状态」巡检（定义收窄） | 可选体检 | 商管；责任隔离 |

**首推组合：** V1 + V2 立刻做；V3 有维保期项目再上；V4/V5 有明确预算再谈。

## 4. 技术默认栈（服务于增值点，非平台野心）

| 层级 | 默认做法 | 备注 |
|------|----------|------|
| 主力 | 园工/保安 · 扫码巡检拍照 | 低成本、可培训、可留痕 |
| 主力 | 园区已有摄像头抽帧（非人脸叙事） | 积水、水景、公区异常 |
| 规则 | 合作方低代码规则引擎 | 现场必验「业务能否自己改规则」 |
| 可选 | 极少量液位/关键井传感 | 仅易涝点验证，不当标配 |
| 暂缓 | 高密度地下物联网、自建中台 | 与「非新业务线」冲突 |

**成功指标：** 标书/图纸里有清晰增值点，客户愿意为预留或可选模块付钱——**不是测点密度，也不是自有 ARR。**

## 5. 法律与话术边界（合同与投标必须同口径）

| 可写 | 不可写 |
|------|--------|
| 地表积水、雨水口、覆土过湿等表症巡检 | 「保证结构不渗漏 / 防渗漏合规」 |
| 长势异常过程记录与派单建议 | 单方面替代质保鉴定、判定施工不合格 |
| AI 辅助 + 专业人员复核 | 全自动免责、替代专项工程师 |
| 异常发现后转介土建/防水/机电 | 我方背书专项责任 |

**对外一句：** 让景观「可管理、可证明、可移交」；  
**对内一句：** 增值点帮设计多收费、好中标；平台与硬件尽量别人扛。

## 6. 选型「杀手锏」三问（合作/甲采都适用）

1. **误报如何压到一线愿意看、而不是关通知？**（树影、反光、落叶）  
2. **弱网/断电如何缓存补传？** 室外链路是什么制式？  
3. **规则是否低代码？** 业务能否配置类似：  
   `连续降雨>50mm 且 关键井液位>阈值 → 预警分区并派单`

另问：无传感器时的最小可售版本、企微/私有化/API、实施费与年费比例、与设计院分润先例。

## 9. 给管理层的结论句（可直接用于周会）

> 郑州此行确认：合作方在**孪生工单闭环**与**种植感知工程化**上有可借鉴的成熟能力，但**不构成贝尔高林新开 AI/IoT 业务线的理由**。  
> 正确用法是：把这些能力拆成景观项目的 **V1–V5 增值点**，服务设计溢价与投标差异化；平台与硬件优先白标或甲方自采，我方做场景、规范、选型与接口。  
> 场景锚定园区 / 酒店 / 公建 / 城更；**远离农田物联网自营叙事**。  
> **先改图纸与标书，再谈可选模块；先项目利润，再谈任何平台野心。**
